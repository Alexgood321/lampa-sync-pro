# Lampa Sync Pro

Плагин синхронизации прогресса просмотра между **Android TV, macOS, iPhone и iPad** через отдельный проект Supabase.

> **Статус: доступна тестовая версия JS-плагина 0.1.15-alpha, Supabase/RPC/RLS развёрнуты.** 233 клиентские и 30 SQL-проверок выполнены. **На iPhone и Mac подтверждена синхронизация выбранной серии; таймкод внешних VLC/IINA не подтверждён. Android TV/iPad пока не проверены.** Плагин опубликован в персональном My Store как тестовая альфа-версия; полноценное использование требует проверки на устройствах.

## Плагин 0.1.15-alpha

- [Установка и ограничения](docs/PLUGIN_ALPHA.md) · [`lampa-sync-pro.js`](lampa-sync-pro.js).
- Вход через email/password в Supabase Auth, хранение токенов в IndexedDB (fallback: localStorage).
- Сбор подтверждённого торрент-прогресса, опрос TorrServer `POST /viewed` с включённым TrackTimecode и offline-очередь; CUB/Trakt/HDRezka не изменяются.
- **Быстрое продолжение и изображения серий:** при открытии карточки с сохранённым торрентом Sync Pro заранее запрашивает `file_stats` и кратковременно кеширует результат **в оперативной памяти на 90 секунд** по аккаунту, URL TorrServer и хешу. При нажатии «Продолжить» повторный запрос не требуется, если кеш готов. Список файлов отображается сразу, а данные TMDB (`Api.seasons`: кадры, названия, даты выхода) подгружаются **после открытия** и обновляют элементы без пересоздания списка; изображения вне экрана загружаются лениво. Сохранённая серия остаётся выделенной, автозапуска нет. При отсутствии кеша или ошибок API доступны прежние безопасные резервные механизмы. NUM, HDRezka, CUB, Trakt и Realtime не изменены.
- Облачное состояние передаётся по **Supabase Realtime WebSocket**: после изменения ревизии устройства мгновенно подтягивают snapshot. **Постоянного HTTP-опроса нет**. На запуске, при переподключении, возвращении в Lampa и открытии карточки выполняется проверка пропущенных изменений.
- Smoke-тесты: [авторизация/очередь](tests/plugin_smoke.js) (30), [возобновление](tests/resume_smoke.js) (90), [автоповтор TorrServer](tests/torrent_resume_retry_smoke.js) (11), [TorrServer](tests/torrserver_viewed_smoke.js) (25), [режим без опроса](tests/auto_sync_smoke.js) (16), [Realtime WebSocket](tests/realtime_smoke.js) (61). GitHub Actions запускает все шесть.

## Реализовано в Supabase

- Шесть изолированных таблиц, RLS, запрет прямой записи с клиента.
- Транзакционный RPC для отправки событий с дедупликацией и защитой от устаревших ревизий.
- RPC для snapshot, delta-pull и получения продолжения конкретной карточки.
- 30 SQL regression assertions, включая проверку нового metadata-only Lampac источника и ручных отметок; тестовые данные откатились. В Realtime включена только таблица `lsp_sync_heads`.
- [Протокол и HTTPS RPC](docs/API_V1.md) · [Realtime](docs/REALTIME.md) · [Интеграция продолжения](docs/CONTINUE_INTEGRATION.md) · [Миграции](supabase/migrations/) · [SQL-тесты](tests/lampac_sql_smoke.sql).

В реальном тесте iPhone → Mac подтверждены авторизация, история серии и отображение кнопки продолжения. Точные таймкоды через VLC/IINA не подтверждены; новое чтение `/viewed` ещё нужно проверить на устройствах. CUB/Trakt не затронуты.

## Цель

Начать просмотр фильма или серии на одном устройстве и продолжить на другом, сохранив выбранный эпизод, источник и позицию воспроизведения, **без передачи видеопотока через Supabase**.

## Совместимость

- Lampa: встроенная история и таймлайн.
- TorrServer: идентификация раздачи по infohash и файла по индексу/пути, чтение TrackTimecode.
- NUM Series Pro 2.0.7: чтение облачных состояний серий, продолжение из облака, отправка ручных отметок и отмена массовых действий. Нативный Timeline не перезаписывается из облака.
- Lampac: собственный онлайн-адаптер, сохраняет только ID источника, озвучку, серию и доступный прогресс.
- HDRezka: пока работает отдельно; её адаптер и миграция истории ещё не реализованы.
- CUB и Trakt: не заменяем и не перезаписываем их данные без отдельной согласованной интеграции.

## Архитектура

```text
Android TV · Mac · iPhone · iPad
             |
       Lampa Sync Pro
             |
       HTTPS REST API
             |
      Supabase PostgreSQL
```

- Только метаданные просмотра: идентификаторы карточек, сезон/серия, позиция/длительность, тип источника, ссылка на файл через infohash и file_index/path (без токенов доступа к потокам).
- Без облачной передачи самих фильмов.
- Идемпотентная запись и контроль конфликтов при переключении устройств.
- Работа без сети: локальные изменения сохраняются до восстановления соединения. WebSocket переподключается с экспоненциальной паузой до 30 секунд, периодический ping каждые 20 секунд поддерживает соединение. На iOS при сворачивании подключение закрывается и восстанавливается после возврата.
- Конфиденциальность: RLS, авторизация устройств, отсутствие секретных серверных ключей в клиентском JavaScript.

## Безопасность изменений

Размещение в My Store настраивается через `lampa-plugins.json` этого репозитория и allowlist реестров в `store`; рабочие файлы других плагинов не затрагиваются. В репозитории находится только **публичный publishable key** Supabase. Приватные секреты, пользовательские токены и дампы прогресса не коммитятся.

## Проект Supabase

Отдельный проект **Lampa Sync Pro**, регион `eu-west-1`. Конфигурация и учётные данные остаются вне GitHub.

## Публикация в My Store

Манифест `lampa-plugins.json` регистрирует JS в разделах «Мои» и «Рейтинги и сервисы». Централизованная синхронизация фиксирует SHA и версию из `var VERSION`, а My Store сравнивает её с установленной ссылкой. После применения обновления код запускается при следующем старте Lampa.

`.github/workflows/notify-store.yml` отправляет `repository_dispatch` при изменении JS или манифеста. Для немедленных обновлений необходимо **однократно** добавить Actions secret `STORE_DISPATCH_TOKEN` с Contents: Read and write для `Alexgood321/store`. Без секрета обновления могут находиться резервным периодическим сканированием магазина, но немедленная доставка событий не работает.
