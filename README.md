# Lampa Sync Pro

Плагин синхронизации прогресса просмотра между **Android TV, macOS, iPhone и iPad** через отдельный проект Supabase.

> **Статус: серверная часть развернута и проверена (Supabase, RPC v1, RLS).** Рабочий плагин Lampa ещё не создан. Не добавляйте URL этого репозитория в Lampa как готовое расширение.

**Результат первого этапа:** аудит и спецификация сохранены. Реальные API, таблицы и плагин не развёрнуты.

## Реализовано в Supabase

- Шесть изолированных таблиц, RLS, запрет прямой записи с клиента.
- Транзакционный RPC для отправки событий с дедупликацией и защитой от устаревших ревизий.
- RPC для snapshot, delta-pull и получения продолжения конкретной карточки.
- 15 SQL regression assertions без сохранения тестовых данных; 0 замечаний Security/Performance Advisors.
- [Протокол и реальные HTTPS RPC](docs/API_V1.md) · [Миграции](supabase/migrations/) · [Тесты](tests/supabase_smoke.sql).

Авторизация реальных устройств, клиентский плагин и E2E ещё не реализованы. Подключение через CUB/Trakt не изменено.

## Цель

Начать просмотр фильма или серии на одном устройстве и продолжить на другом, сохранив выбранный эпизод, источник и позицию воспроизведения, **без передачи видеопотока через Supabase**.

## Совместимость, которую планируем

- Lampa: встроенная история и таймлайн.
- TorrServer: идентификация раздачи по infohash и файла по индексу/пути, чтение TrackTimecode.
- NUM Series Pro: сезон, серия и отметки просмотра.
- HDRezka: отдельный адаптер к существующему прогрессу, без разрушения текущей синхронизации.
- CUB и Trakt: не заменяем и не перезаписываем их данные без отдельной согласованной интеграции.

## Архитектура

```text
Android TV · Mac · iPhone · iPad
             |
       Lampa Sync Pro
             |
       HTTPS REST API
             |
      Supabase PostgreSQL
```

- Только метаданные просмотра: идентификаторы карточек, сезон/серия, позиция/длительность, тип источника, ссылка на файл через infohash и file_index/path (без токенов доступа к потокам).
- Без облачной передачи самих фильмов.
- Идемпотентная запись и контроль конфликтов при переключении устройств.
- Работа без сети: локальные изменения сохраняются до восстановления соединения.
- Конфиденциальность: RLS, авторизация устройств, отсутствие секретных серверных ключей в клиентском JavaScript.

## Этапы

1. ✅ Аудит исходников и протокол синхронизации.
2. ✅ Таблицы, политики RLS, транзакционные RPC и SQL-тесты Supabase.
3. ⏳ Реализовать автономный клиентский плагин с безопасной авторизацией.
4. Подключить TorrServer/NUM и проверить на двух устройствах.
5. Подключить HDRezka, проверить конфликты с CUB/Trakt.
6. Только после E2E-проверок опубликовать установочную ссылку в собственном магазине Lampa.

## Безопасность изменений

Существующие рабочие репозитории `lampa-plugins`, `store` и `lampa-hdrezka` не изменяются в ходе подготовки. Ключи Supabase, пользовательские токены и дампы прогресса не коммитятся.
