# Lampa Sync Pro 0.1.2-alpha

**Статус:** устанавливаемая тестовая версия. SQL/API развёрнуты; автоматические тесты без реальных устройств пройдены. **На iPhone → Mac подтверждена передача названия/серии и появление кнопки продолжения, но реального таймкода через VLC/IINA не было.** Android TV/iPad не проверены. Плагин зарегистрирован в собственном My Store; проверка доставки обновления каталога отдельно.

## Установить для тестирования

Исходник: [`lampa-sync-pro.js`](../lampa-sync-pro.js).

Адрес для установки через **Lampa → Настройки → Расширения → Добавить**:

```text
https://cdn.jsdelivr.net/gh/Alexgood321/lampa-sync-pro@d8cfdc99f3b60c9e508bd9ff9c31621923720cc6/lampa-sync-pro.js
```

Это зафиксированная версия из commit `d8cfdc99`; содержимое сохранится при следующих коммитах. Постоянный URL, через который My Store отслеживает актуальный исходник: `https://cdn.jsdelivr.net/gh/Alexgood321/lampa-sync-pro@main/lampa-sync-pro.js`.

На старой версии 0.1.0-alpha Lampa показывала статус **500**, потому что JS содержал сокращение `L`, а штатный текстовый анализатор ищет `Lampa.`. В 0.1.1-alpha присутствуют реальные обращения к `Lampa.Plugins`, автоматическое имя установленной записи и реестр запуска. **200 означает только, что текст распознан**, а не доказательство успешного запуска и синхронизации. После замены URL перезапустить Lampa.

## Первый вход

1. В Lampa откройте **Настройки → Lampa Sync Pro**.
2. Выберите «Зарегистрироваться», если это первое подключение. Введите **email и новый пароль для этого проекта Supabase**, не пароль от GitHub/HDRezka/CUB.
3. При требовании подтверждения email завершите регистрацию через письмо. Если ссылку подтверждения отправляет на недоступный localhost, проверьте подтверждение аккаунта и затем войдите обычным способом; конфигурация Auth Site URL ещё не проходила проверку.
4. Выберите «Войти» с теми же данными на каждом устройстве. Для всех устройств используется **один аккаунт Supabase Auth**.
5. Нажмите «Синхронизировать сейчас» и проверьте состояние: email, число ожидающих событий, серверную ревизию.
6. При просмотре торрента с подтверждёнными `infohash`, `file_index`, `file_path`, media ID, сезоном/эпизодом плагин фиксирует события. Откройте карточку на другом устройстве и проверьте кнопку «☁ Продолжить».

**Пароль не сохраняется.** Supabase user access/refresh tokens сохраняются в IndexedDB, а если она недоступна — в `localStorage` текущего origin Lampa. Это обычное клиентское хранилище, доступное другим исполняемым в том же origin расширениям. Сторонние плагины должны быть доверенными. При смене/выходе пользователя очередь и кэш очищаются.

## Реализовано

- Регистрация и вход через Supabase Auth email/password, обновление user JWT.
- Authenticated REST RPC без серверного `service_role`/secret в браузере.
- Устройство и монотонный `device_seq`, `event_id`, локальная очередь, повтор после сети.
- События `started`, `progress`, `paused`, `stopped`, `completed` для идентифицированного **торрента**.
- Захват штатных `Lampa.Player` и `Lampa.Timeline` событий. Для HTML5-плеера таймкод читается из `PlayerVideo.timeupdate`. При включённом `torrserver_tracktimecode` плагин дополнительно читает `POST /viewed` по `infohash + file_index` при запуске, каждые 15 секунд и после остановки. Извлечённый положительный таймкод отправляется через Supabase RPC только при подтверждённой привязке к эпизоду.
- Подтягивание облачного snapshot при входе и каждые две минуты; обновление указателя при открытии карточки.
- Кнопка на карточке: выбирается `infohash` и конкретный файл, при необходимости TorrServer пытается добавить торрент по hash-only magnet, затем штатный `Lampa.Player.play`.
- Для завершённой серии при наличии **следующей серии в той же раздаче** кнопка переключается на неё.
- Все видеопотоки остаются между клиентом и TorrServer; в Supabase отправляется только whitelist метаданных.
- **Не меняет** существующие CUB, Trakt, HDRezka/Netlify, NUM Series Pro, панель TorrServer и `localStorage` ключи их настроек.

## Ограничения 0.1.2-alpha

- В настройках добавлена кнопка **«Проверить таймкод TorrServer»**. «Синхронизировать сейчас» также выполняет проверку последнего эпизода перед отправкой очереди. Если TorrServer возвращает 0 или пустой массив, прогресс не выдумывается и не отправляется.
- **Ручные отметки NUM** и автоматическая двусторонняя запись в нативный Lampa Timeline пока не поддерживаются. Существующая история CUB/Trakt не импортируется.
- **HDRezka** пока не синхронизируется с этой новой БД; её собственная Netlify-синхронизация продолжает работу.
- Для **внешних плееров** точное время известно только при наличии обратного события Timeline. Один запуск Just Player не доказывает реальную позицию.
- Если реальный player event не содержит проверяемого hash, файла, карточки и номера серии, запись намеренно не создаётся.
- Cloud resume использует точное совпадение файла/пути. Если торрента нет, попытка hash-only magnet не гарантирует наличие пиров/метаданных. Выбор файла вручную остаётся запасным путём.
- `source_recipe` не хранит magnet tracker credentials, приватные URL или stream links.
- Отсутствуют push/pull индикаторы UI и полноценное разрешение сложных конфликтов в интерфейсе. Сервер отклоняет устаревшую запись, сохраняя журнал `applied:false`; клиент показывает уведомление о пропуске.
- На больших историях `snapshot` ограничен 2500 записями. Client-side восстановление истории через курсор `pull` пока не добавлено.
- Auth Email Provider, подтверждение писем, CORS, IndexedDB и режим CUB на реальных устройствах требуют проверки.

## Разработка и проверки

```bash
node --check lampa-sync-pro.js
node tests/plugin_smoke.js
node tests/resume_smoke.js
node tests/torrserver_viewed_smoke.js
```

Все тесты используют имитацию Lampa, TorrServer и ответов Supabase, **не настоящие видеоплееры или подписанный user JWT**.

Проверенные сценарии: Auth, offline-очередь, отсутствие приватных URL в событиях, ревизии, кнопка продолжения, выбор эпизода и точной позиции, переход к следующей серии, выход из аккаунта. В SQL-примерах все синтетические данные откатываются.

## Безопасность релизов

- Отдельный репозиторий и проект Supabase, никакого изменения рабочего Store или текущих плагинов.
- GitHub Actions проверяет JS-синтаксис и оба smoke-теста на новых коммитах.
- Для отката клиентской части удалить альфу из Lampa либо заменить JS на прежний commit SHA.
- Миграции базы аддитивны; данные не удаляются при откате JS.
- Для E2E сначала тестовый сериал и отдельный тестовый аккаунт, затем реальные просмотры.
