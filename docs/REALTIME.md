# Lampa Sync Pro: событийная синхронизация (0.1.6-alpha)

## Принцип работы

1. Lampa создаёт локальное событие `started`, `progress`, `stopped` и ставит его в надёжную очередь IndexedDB / localStorage.
2. Через ~1,8 секунды очередь отправляется в существующий транзакционный Supabase RPC `lsp_sync_push`. Успешный коммит увеличивает `public.lsp_sync_heads.revision`.
3. В публикации `supabase_realtime` присутствует **только `public.lsp_sync_heads`**: `user_id`, `revision`, `updated_at`. В Realtime не транслируются названия фильмов, torrent infohash, источники потока и пароли.
4. Клиенты подписаны на `postgres_changes` с `filter: user_id=eq.<auth.uid()>`. Для строки действует RLS `user_id = auth.uid()`; у роли `anon` нет `SELECT`.
5. Если подписанный пользователь получил **более высокую ревизию**, клиент одним защищённым RPC `lsp_sync_snapshot` забирает новые данные. Повторные уведомления сворачиваются; старые и чужие игнорируются.

## Протокол и транспорт

- Без внешнего npm/JS-загрузчика. Использован документированный Phoenix JSON WebSocket 1.0.0, `wss://kkrmivgrnfqauvplccqm.supabase.co/realtime/v1/websocket`.
- Только публичный ключ Supabase передаётся в URL. Auth JWT идёт в `phx_join.payload.access_token`, обновляется через `access_token` внутри защищённого WebSocket.
- Heartbeat: 20 секунд. При отсутствии подтверждения / закрытии соединения: повтор с задержками 1, 2, 4, 8, 16 и 30 секунд.
- После нового успешного подключения, запуска Lampa и возвращения из фона клиент запрашивает snapshot, чтобы восполнить изменения за время отсутствия соединения.
- При уходе Lampa в фон WebSocket закрывается. Регулярный HTTP-опрос 30 секунд **удалён**.
- При отсутствии поддержки WebSocket остаются штатные кнопка «Синхронизировать сейчас», обновление при запуске/возврате, запрос конкретной карточки и отправка событий по RPC.

## Изоляция и ограничения

NUM Series Pro 2.0.7 использует API Sync Pro для облачных отметок, не изменяя нативный Timeline; `HDRezka`, `CUB`, `Trakt` и настройки TorrServer не затрагиваются. Realtime не создаёт таймкоды VLC/IINA. Во время синхронизации облако не транслирует пользовательские токены или URL видеопотоков.

**Статус проверки:** SQL-публикация активирована, RLS и ограничения прав подтверждены, 45 сценариев WebSocket пройдены на имитации клиента. Срабатывание подписки в настоящих WebView iPhone, Mac и Android TV требует отдельного E2E-теста; синтетические проверки не доказывают работу всех платформ.

## Откат

Клиент: вернуть предыдущий закреплённый URL `https://cdn.jsdelivr.net/gh/Alexgood321/lampa-sync-pro@7f0aa6e38ab13672a43800bcedddf1a99ff860d0/lampa-sync-pro.js` (версия 0.1.4-alpha). Схему БД для этого менять не требуется: публикация `lsp_sync_heads` не влияет на старого REST-клиента.

При необходимости отказаться от Realtime на сервере: `ALTER PUBLICATION supabase_realtime DROP TABLE public.lsp_sync_heads;`. Перед этим убедиться, что больше нет клиентов 0.1.5/0.1.6, которым нужны push-уведомления.
