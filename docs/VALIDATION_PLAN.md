# Проверки и критерии готовности

**Статус:** тест-план, а не отчёт о пройденном E2E.

## Очерёдность внедрения

| Фаза | Действие | Критерий |
|---|---|---|
| 0 | Анализ исходников и спецификация | Утверждены идентификаторы, события, модель конфликтов и исключения из синхронизации |
| 1 | SQL-миграция + RLS + Auth на отдельном Supabase | Два тестовых пользователя не читают чужие данные; повторный `event_id` не дублирует изменение |
| 2 | Клиент Lampa: только capture + cloud write/read | Прогресс пишется и читается на тестовых объектах без вмешательства в Timeline |
| 3 | TorrServer/NUM: применение синхронизированного прогресса | Одинаковая серия/позиция на TV и Mac; ручные отметки не теряются |
| 4 | iOS/iPadOS и отказоустойчивость | Offline/restart, потеря сети, долгий фон, повторная доставка |
| 5 | Адаптер HDRezka | Netlify и Supabase не перезаписывают друг друга, секреты не передаются |
| 6 | Релиз в личный магазин | Smoke-тест на всех четырёх устройствах + откат на предыдущий SHA |

## Базовые E2E-сценарии

1. **TV → Mac:** открыть S02E05 на TV, 18:40/45:00, закрыть, открыть карточку на Mac, выбрать продолжение. Допуск позиции — ±5 секунд при подтверждённом checkpoint; видеопоток должен оставаться прямым.
2. **Mac → iPhone/iPad:** тот же сценарий, но только для источников, которые реально открываются на iOS.
3. **Порог окончания:** завершённая серия (≥90%) предлагает следующую существующую серию; не перепрыгивать сезон или специальный выпуск без подтверждённых данных.
4. **Два разных торрента:** один эпизод из разных раздач; не путать `file_index`, `infohash` и позицию, сохранять source-specific записи.
5. **Чужой TorrServer:** новый клиент не видит раздачу; не запускать пустой/старый URL, предложить выбрать файл заново.
6. **Внешний плеер:** при отсутствии обратного timecode сохранять только подтверждённые поля, не имитировать точную позицию.
7. **Параллельный просмотр:** TV и Mac на одном сериале; старое устройство закрывается позже, не перетирая более новую серверную ревизию.
8. **Повторная доставка:** одинаковый `event_id` доставлен трижды; применяется один раз, счётчики и история не удваиваются.
9. **Offline:** пять событий записаны без сети; после восстановления доставляются по порядку, конфликт возвращается явно.
10. **Удаление:** удалить отметку на Mac, открыть TV позже; tombstone препятствует возвращению записи из старого кэша.
11. **Очистка локальных данных:** новый клиент загружает историю, но не трогает `rezka_bridge_token`, CUB, Trakt, настройки TorrServer и расширения.
12. **Ручная отметка NUM:** массово отметить сезон, затем отменить; обе операции синхронизируются намеренно и с правильным порядком.
13. **HDRezka:** выбранные translator/provider episode IDs и позиция совпадают с Netlify; страница без TMDb не склеивается с похожим названием.
14. **RLS:** токен A не читает/не меняет строки B; с publishable key без JWT нельзя получить содержимое чужого прогресса.
15. **CORS:** Android TV, iOS и macOS выполняют авторизованные запросы; недоступность Supabase не блокирует интерфейс Lampa.
16. **Быстродействие:** открытие карточки не ожидает сетевого ответа для первичного интерфейса; тайм-аут не зависает, история берётся из кэша с последующей актуализацией.
17. **Безопасность:** в GitHub, Supabase payload/logs отсутствуют HDRezka stream URL, magnet passkey, cookie, токены шлюза.
18. **Rollback:** переключение на прошлый JS SHA не уничтожает историю и оставляет исходный NUM/HDRezka работоспособными.

## Тесты на уровне БД

- Валидация типов события, идентификатора контента и допустимых значений прогресса.
- Запрет отрицательной позиции и невалидного `duration`.
- Атомарность пачки: либо вся пачка, либо ноль изменений.
- Стабильный курсор с пагинацией событий.
- Дедупликация `event_id`.
- Гонки двух независимых устройств на одном `sync_heads`.
- Ревизии сервера строго возрастают в пределах пользователя.
- Нет случайного `SECURITY DEFINER` с широким `EXECUTE`.
- Каждая публично доступная таблица имеет минимальный `GRANT` и RLS.
- Нет silent overwrite завершённого эпизода от старого session_id.

## Go / No-Go

Переход от dry-run к записи в действующий Lampa Timeline только после прохождения тестов 1–12, 14–18. Интеграция HDRezka включается отдельно после теста 13 и подтверждения read-only режима. В магазин плагинов добавлять **только после** E2E на реальных устройствах.
