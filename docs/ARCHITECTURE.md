# Архитектура Lampa Sync Pro

**Состояние:** проектирование. Ничего не развёрнуто в production.

## Принцип

1. Клиент Lampa фиксирует факт подтверждённого начала просмотра, выбранный эпизод и изменения позиции.
2. Локальное хранилище сохраняет запись независимо от доступности сети.
3. Клиент отправляет события по HTTPS в отдельный проект Supabase.
4. Другие устройства получают изменения при запуске, открытии карточки, возврате приложения из фона; периодическое обновление добавляется только при необходимости.
5. Перед запуском выполняется **повторное разрешение источника**: сохранённый stream URL не используется повторно.

## Данные

Минимальные поля для будущей согласованной схемы:

| Поле | Назначение |
|---|---|
| `user_id` | Владелец данных в Supabase Auth |
| `media_ids` | Проверяемые внешние ID: TMDb, IMDb, Кинопоиск |
| `media_type` | Фильм / сериал |
| `season`, `episode` | Номер сезона/эпизода, если применимо |
| `position_seconds`, `duration_seconds` | Позиция и длительность |
| `source_type` | Torrent / HDRezka / Online |
| `source_recipe` | Разрешённые метаданные для повторного поиска потока; без секретов |
| `state` | Started / In progress / Completed |
| `event_id`, `device_id`, `revision` | Идемпотентность и разрешение конфликтов |

Для торрент-файла `source_recipe` содержит `infohash`, `file_index`, `file_path` (где допустимо), но не видеопоток. Для HDRezka интеграцию делаем отдельно после проверки существующего контракта плагина.

## Согласование данных

- **Не использовать время устройства как единственный арбитр**: часы устройств могут расходиться.
- Первичная загрузка не должна перезаписывать облачную историю пустыми или более старыми локальными данными.
- Применять идемпотентные `event_id` и серверный `revision`, чтобы предотвращать потерю обновлений.
- Прогресс обновлять с ограничением частоты и финально фиксировать при остановке/переключении файла.
- Отметка завершения серии не должна сбрасываться фоновым событием со старого устройства.
- Удаления должны синхронизироваться как явные события (tombstones), а не исчезновение строки.
- Отсутствие сети не блокирует просмотр. Очередь событий уходит при следующем соединении.

## Границы интеграции

- **TorrServer:** включённый TrackTimecode читается как потенциальный источник позиции, но при конфликте потребуется единая политика приоритета; записи на TorrServer делать только после подтверждения воспроизведения.
- **NUM Series Pro:** сначала только чтение прогресса и сезонов, затем разрешённый двусторонний обмен.
- **HDRezka:** существующую систему синхронизации на Netlify не менять, подключаться через отдельный адаптер и проверять согласование.
- **CUB/Trakt:** оставить штатную работу; не пытаться синхронизировать весь localStorage Lampa.
- **Плееры:** сохранить штатный запуск Lampa/Just Player+, без собственного медиасервера.

## Безопасность

- Supabase Auth + RLS по `auth.uid()` для каждой доступной из клиента записи.
- В JS допустим только публичный (publishable) ключ Supabase; `service_role`/secret не публикуются.
- Привязка устройств осуществляется к одному аутентифицированному владельцу, без единого общедоступного идентификатора.
- Секреты потоков, авторизационные cookie и персональные токены источников не отправляются в облачную историю.
- Логирование без токенов и полного содержимого `source_recipe`.

## Приёмка перед публикацией

1. Android TV → Mac: та же серия и позиция, если поток на Mac доступен.
2. Mac → iPhone/iPad: аналогично, включая переход к следующей серии при завершении.
3. Два устройства с разными позициями одновременно: не теряется более новое подтверждённое состояние.
4. Режим offline → online: очередь записей доставляется ровно один раз.
5. Очистка localStorage на одном устройстве: загрузка облачной истории не стирает другие данные.
6. Смена торрента, отсутствие сидов, удалённая раздача: понятное восстановление/ошибка без зависаний.
7. HDRezka и CUB/Trakt продолжают работать без изменений.
8. Проверены RLS, попытка доступа другим пользователем, логи и отсутствие секретов в GitHub.

## Развёртывание

Деплой и публикация ссылок в магазине **только после проверок**. Любое изменение имеющихся плагинов и Supabase-схемы требует резервной копии и понятного отката.
